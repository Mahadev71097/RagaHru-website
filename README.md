# RAGAHRU

The RagaHru marketplace — a premium catalogue of wedding website templates.

Every template is shown **only as a preview video inside a mobile phone frame**.
The real wedding website (its HTML, CSS and JavaScript) is never loaded here —
there are no iframes, no live previews and no embedded template files anywhere
in this project. Visitors see a video; nothing more.

Built with plain HTML, CSS and vanilla JavaScript. No build step, no framework,
no backend, no database. It can be dropped straight onto Netlify, GitHub Pages,
Cloudflare Pages or any other static host.

│   ├── logo/                   logo.svg, favicon.svg
│   └── icons/                  whatsapp, music, rsvp, close (SVG)

│   └── sync-templates.bat      double-click to run it

**The `templates/` folders hold preview media only.** No wedding website HTML
belongs in them. The actual wedding websites stay in a separate, private
project of your own.

## 2. WHERE TO PUT YOUR PREVIEW VIDEOS

```
templates/hindu/template-01/preview/preview.mp4
templates/christian/template-02/preview/preview.mp4
templates/islamic/template-03/preview/preview.mp4
```

The shape is always `templates/<collection>/<folder>/preview/preview.mp4`,
and the registry builds that path for you — see section 3.

**The video is the preview.** This project is video-only: there are no poster
images, and none are required.

Nothing breaks while a video is missing:

1. If `preview.mp4` exists → it plays, muted and looping, in the hero and in
   its collection.
2. If it is missing → an elegant "Preview coming soon" plate is shown inside
   the phone.

A still frame is still *supported* if you ever want one: export a 1080x1920
JPG, put it beside the video, and add a `posterPath` line to that template.
It then covers the moment before the first video frame decodes, and stands in
if the video ever fails. Entirely optional.

## 3. HOW TO ADD TEMPLATE 04

**Step 1 — create the folder**

```
templates/hindu/template-04/preview/
```

**Step 2 — put the video inside it**

```
templates/hindu/template-04/preview/preview.mp4
```

### The quick way: paste the folder, run one file

A static website cannot read your hard drive — the browser only receives files
it asks for by name, so the page cannot find a new folder on its own. This
script does the looking for you:

**Double-click `tools/sync-templates.bat`** (or run `node tools/sync-templates.js`).

It scans `templates/`, adds any folder that is not yet in the registry, gives
it today's date so it lands first with a NEW badge, and tells you which
templates are still waiting for a `preview.mp4`. Existing entries are never
touched, reordered or deleted — a template whose folder has vanished is only
reported.

Then open `js/templates.js` and edit the new entry's `name` and
`description`, since those cannot be guessed from a folder name.

So the whole flow is:

1. Paste `templates/hindu/template-05/preview/preview.mp4`
2. Double-click `tools/sync-templates.bat`
3. Edit the name and description
4. Refresh

The manual steps below do the same thing by hand.

**Step 3 — open `js/templates.js`**

**Step 4 — add one object to the list.** Put a comma after the previous
object, then paste this and change the values:

```js
{
  id: "hindu-02",
  name: "Template 04",
  religion: "hindu",
  description: "A modern Hindu wedding invitation with a quiet, editorial feel.",
  price: 999,
  originalPrice: 1499,
  music: true,
  rsvp: true,
  previewPath: "templates/template-04/preview/preview.mp4",
  createdAt: "2026-09-10"
}
```

**Step 5 — save and refresh the page. That is all.**

| Field           | What it does                                                        |
| --------------- | ------------------------------------------------------------------- |
| `id`            | Unique text id. Never repeat one.                                    |
| `name`          | Shown under the phone and used in the WhatsApp message.              |
| `collection`    | `"hindu"`, `"christian"`, `"islamic"` — or any new one you invent.   |
| `folder`        | The folder name inside that collection, e.g. `"template-04"`.        |
| `description`   | One or two short lines shown under the name.                         |
| `price`         | The selling price. Number only, no `₹`.                              |
| `originalPrice` | The struck-through price. Number only.                               |
| `music`         | `true` shows "Music Available".                                      |
| `rsvp`          | `true` shows "RSVP".                                                 |
| `multilingual`  | `true` shows the highlighted "Multilingual" badge.                    |
| `previewPath`   | Optional. Built from `collection` + `folder` unless you set it.      |
| `posterPath`    | Optional. A still frame for loading/fallback. Omit for video-only.   |
| `createdAt`     | `"YYYY-MM-DD"`. The newest date appears first.                       |

### The hero showcase

The three phones in the hero read the same registry. A template joins the
rotation automatically as soon as it has a `previewPath` — there is nothing
to add anywhere else. With three templates the hero cycles those three; with
more, it works through the collection, never showing the same template on two
phones at once. Only the phones on screen hold a loaded video, and the next
one is warmed in the background, so a large catalogue stays light.

### Adding a whole new collection

House warming, baby shower, birthday — the site is not limited to weddings.

1. Create `templates/housewarming/template-01/preview/preview.mp4`
2. Add an entry with `collection: "housewarming"`
3. Optionally add a nicer heading and choose its position in
   `config/site-config.js`:

   ```js
   { key: "housewarming", label: "House Warming" }
   ```

A new section and its navigation link both appear on their own. A collection
with no templates never renders, so folders can exist long before videos do.
Use hyphens for multi-word names — `baby-shower` becomes "Baby Shower".

### What happens automatically

- **Grouping.** `collection: "hindu"` puts the card in **HINDU WEDDINGS**,
  and an unknown collection creates its own section. You never touch
  `index.html` — the sections and the navigation are both generated.
- **Sorting.** Every section is sorted by `createdAt`, newest first. You never
  reorder cards by hand.
- **Empty sections.** A religion with no templates is hidden completely — its
  heading and its navigation link both disappear.
- **WhatsApp.** The button builds its own link and message from `name`.

## 4. HOW TO CHANGE YOUR WHATSAPP NUMBER

Open **`config/site-config.js`** and edit one line:

```js
const SITE_CONFIG = {
  whatsappNumber: "YOUR_WHATSAPP_NUMBER",
  ...
};
```

Use the **full international format, digits only** — no `+`, no spaces,
no dashes. India's country code is `91`:

```js
whatsappNumber: "919876543210",
```

Every WhatsApp button on the site updates immediately. The message sent is:

> Hi, I need Template 01 design.

The template name changes for each card automatically, so every enquiry that
reaches you already says which template the client wants — Template 04's card
sends "Hi, I need Template 04 design." You can reword the message in the same
file via `enquiryMessage` — keep `{template}` in it, that is the placeholder
the template name is dropped into.

Until you replace the placeholder number the buttons still work; WhatsApp
simply asks the visitor to pick a contact.

### The hero background film

Optional. Drop a file at `assets/hero/hero.mp4` and the hero gains a slow
background film; leave the folder empty and the hero looks exactly as it does
now. See `assets/hero/README.md` for what to export.

It sits **behind** the espresso ground under a warm scrim, so the dual tone and
the headline contrast never depend on what the video happens to show. Muted,
looping, inline, paused when the hero scrolls away, and not loaded at all for
visitors who ask for reduced motion. Change the path with `heroVideo` in
`config/site-config.js`.

### The design system

The whole palette lives in one block at the top of `css/style.css`:

```css
--ivory      #F6F1E8     --muted-text #6F6559
--espresso   #211B18     --border     rgba(33,27,24,.14)
--champagne  #B59663     --surface    #FBF8F2
--rose       #9A6F67
```

Every other colour token derives from these, so a future template can adopt
the system by overriding this block alone. `--champagne-ink` is the same gold
darkened enough to set type on ivory (4.9:1 rather than 2.5:1) — use it for
text, and `--champagne` for hairlines and icons.

`newForDays` in `config/site-config.js` controls how long a template carries
the NEW badge after its `createdAt`.

### The logo

Save the RagaHru logo as:

```
assets/logo/ragahru-logo.png
```

(`.jpg` and `.webp` also work — the first file that loads is used.) It then
appears in the header, the season-sale opening and the footer, each sized
responsively and never stretched. **Until that file exists the site shows the
RagaHru wordmark instead**, so nothing is ever a broken image.

The square logo lockup is used at a generous size in the sale screen and the
footer. In the header it is capped in height so it stays understated; if you
ever have a horizontal version of the lockup, drop it in as the same filename
and the header will read better still.

### The season sale

`js/sale.js` shows the opening announcement once per browsing session — a
refresh does not replay it. It runs about four seconds and can be skipped by
clicking, or with `Esc`. To change the wording, edit the `.sale` block in
`index.html`.

### Custom build

`config/site-config.js` holds `customPrice` and `customMessage` for the
Custom Build section that sits after the collections.

### The brand name

`config/site-config.js` also holds the brand:

```js
brandName: "RagaHru",
```

That one value drives the watermark drawn over every preview video. The
wordmark in the header, the hero and the footer is written into
`index.html`, and the logo files live in `assets/logo/`.

## 5. RECOMMENDED PREVIEW VIDEO SETTINGS

| Setting     | Value                                                  |
| ----------- | ------------------------------------------------------ |
| Resolution  | 1080 × 1920                                            |
| Aspect      | 9:16 (vertical)                                        |
| Format      | MP4, H.264 video + AAC audio                           |
| Frame rate  | 30 fps                                                 |
| Duration    | 10–20 s for the collection preview on the home page    |
|             | 30–60 s for a longer, detailed preview                 |
| File size   | Aim for 2–5 MB. Under 8 MB keeps the page fast.        |
| Audio       | Not needed — previews always play muted                |
| Poster      | Not used — this project is video-only                   |

The videos are lazy-loaded and only play while they are on screen, so the page
stays fast even with 50–100+ templates. Still, keep the files small — every
visitor on a phone pays for them.

## 6. HOW TO RUN AND TEST THE SITE LOCALLY

**The easiest way:** double-click `index.html`. It opens in your browser and
everything works.

**The better way** (matches how a real host serves it) — open a terminal in
this folder and run one of these, then visit <http://localhost:8000>:

```bash
python -m http.server 8000
```

```bash
npx serve .
```

While testing, check:

- each phone plays its video, or falls back to the poster
- the three sections appear in order and newest cards come first
- clicking a phone opens the large preview modal, and `Esc` closes it
- the WhatsApp buttons open a chat with the right template name
- the page looks right at 1440, 1200, 1024, 768, 480, 390 and 375 px wide

## 7. DEPLOYING

The site is fully static, so any of these work with no configuration:

- **Netlify** — drag this folder onto the Netlify dashboard, or connect the
  repository. No build command; publish directory is `/`.
- **GitHub Pages** — push the folder to a repository, then
  *Settings → Pages → Deploy from a branch → main → / (root)*.
- **Cloudflare Pages / Vercel** — same idea; no build step.

Make sure the `.mp4` and `.jpg` files inside `templates/` are committed and
uploaded, otherwise every card falls back to "Preview coming soon".

## 8. COPY PROTECTION — WHAT IS AND IS NOT PROTECTED

What this site does:

- the wedding website itself is **never** served here — only a video
- no iframes, no live previews, no template URLs anywhere in the source
- right-click is disabled
- images and videos cannot be dragged out
- text selection is disabled except where it is genuinely useful
- no download button, no fullscreen, no native video controls
- a subtle "RagaHru" watermark sits over every preview

What no website can prevent, including this one:

- screenshots
- screen recording
- saving a video that has already been downloaded by the browser

That is why the strongest protection here is structural: the real template is
simply not present in this project. Keep it that way.

## 9. BROWSER SUPPORT

Modern Chrome, Edge, Safari and Firefox — desktop and mobile. Videos play
muted, looping and inline, which is what allows autoplay on iOS and Android.
Older browsers without `IntersectionObserver` still see the previews; they just
load them all at once.
